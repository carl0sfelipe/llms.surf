`OPENROUTER_API_KEY`, `OPENCODE_TOKEN`, the bare provider names, `HOME`
and `PATH`, runs `resolve("tier:cheap", …)` with an empty FILE
credential set, and asserts every non-keyless entry is skipped
(`SkipReason::NoFileCredential`) and the chain carries keyless legs

## Findings

1. `gap` (closed by this spec) — law L4 / incident E5-M5. Before T17,
   M9 survived all 7 tests on `main`; reproduced here before adding the
   test (baseline run on main is the T06 report's `expect survival`
   row). Killer is `l4_holds_regardless_of_env` in
   `tests/env_isolation.rs`.
2. `note` — the poison set mandated by the spec
   (`OPENROUTER_API_KEY`, `OPENCODE_TOKEN`, `HOME`, `PATH`) alone would
   NOT kill a literal `std::env::var(p)` mutation (provider names are
   lowercase, `env::var` is an exact match, so `var("openrouter")`
   misses `OPENROUTER_API_KEY`). The test therefore also poisons the
   bare provider names (`openrouter`, `opencode`), which kills both the
   literal variant and the conventional-suffix variant used in the
   scratch mutation. `HOME`/`PATH` poison the generic process env for
   any future gate that resolves credential files or binaries.
3. `note` — env vars are process-global, so the whole mechanism is one
   `#[test]` fn (no `serial_test` dep, no intra-binary race); other
   test files are separate binaries and never touch env, confirmed by
   the `--no-fail-fast` mutation run above.
4. `note` — `l3_cheap_order` (known ~20% stable-sort tie flake on
   `main`) passed on every run in this task (3 full branch/scratch
   runs); no flake observed, `src/` untouched.
