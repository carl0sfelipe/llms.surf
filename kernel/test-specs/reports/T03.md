# T03 — Differential vs the Python it replaces (generated inputs)

## Verdict: FAIL

The Rust kernel diverges from the reference (Python `_resolve_tier_cheap` +
the `run-with-fallback.sh` credential gate) on **generated** inputs: 618
mismatches in 2250 iterations. Every mismatch has one root cause — duplicate
catalog refs whose occurrences disagree on `provider`/`keyless` (shell
collapses the per-ref meta, Rust gates per occurrence). Ordering (L3), dead-id
gate (L2), empty-ref dropping and the paidcorp/allowlist expected difference
all matched.

## Findings

1. **[gap] (L4 / shell-gate port) Duplicate catalog refs with conflicting
   metadata: Rust gates per occurrence, the shell reference gates per ref.**
   `run-with-fallback.sh` builds one `(provider, keyless)` per ref (dict,
   last file occurrence wins) and applies it to every printed occurrence, so
   on duplicates it can (a) keep N copies Rust drops, (b) drop copies Rust
   keeps, and in the degenerate all-duplicates case (c) exit 2 where Rust
   exits 0. 618/618 mismatches in the differential are this class
   (605/2000 main batch ≈ 30%, driven by the generator's duplicate rate:
   size 0–40 from a 60-ref pool). Rust's per-occurrence behaviour matches
   L4's wording ("a non-keyless **entry** appears only if…") and is promoted
   as a **Decision** (2026-09-19, `kernel/laws/P1.md`) with two pinning
   vectors; T08 shadow runs must expect exactly this divergence until the
   shell is retired. Reproduction: `## Evidence` minimal reproducers.

2. **[note] (L5) Gate order L2-before-L5 was unpinned: a dead id whose
   provider is outside the allowlist is skipped as `DeadId` and never
   reported as `ProviderOutsideAllowlist`.** Confirmed against both
   implementations (identical behaviour, so not a divergence); now pinned by
   vector `T03_dead_id_gate_precedes_allowlist` so a future reorder of the
   two door gates goes red.
