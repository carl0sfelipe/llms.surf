## Per-law review

### L1 — typed fields, US wire round-trip, delimiters rejected (e82f008)
1. **Statement precise?** Not fully. "Chain fields are typed" is a design
   assertion, not a ∀-property. Proposed ∀-form promoted to `P1.md`
   amendments: "∀ chains `parse_us(r, render_us(c)) == c`; construction
   rejects US/LF in any of the three string fields and an empty `ref`."
2. **Mechanism sufficient?** Mostly, with two corners the generator cannot
   reach: (a) `provider: Some("")` builds, renders as the empty field and
   parses back as `None` — round-trip violated; `entry()` fields are
   min-length-1 so the generator cannot produce it (the spec's exact
   "generator cannot produce the violating case" trap). Probe A. (b)
   Counter-positive: CR fields also cannot be generated, and I suspected a
   `lines()` strip bug there — refuted by probe: CR survives because the
   typed `keyless` bool renders last. The `l3`-style trap is avoided here:
   the round-trip asserts on the parsed output, not a derived value.
   `l1b` coverage is asymmetric (ref+US, id_status+LF, provider+US only),
   though `Chain::new` checks both delimiters uniformly on all three fields.
3. **Incident closed?** For the kernel contract, yes: fixed arity
   (`fields.len() != 4`), typed `keyless: bool` and `provider: Option` make
   the positional collapse unrepresentable. Honestly stated: the pre-fix
   code was shell (`run-with-fallback.sh@753d3cf`), which `tests/laws.rs`
   never executes — the shell-side closure is `bin/test-free-path.sh`
   section 11, outside this law's mechanism. The law pins the *replacement*,
   not the old binary.
4. **Type or test?** `keyless: bool` already is the type that killed the
   incident. A `Provider` newtype adds nothing against the actual failure
   mode (positional, not value); not proposed. The cheap type-fix is the
   empty-provider normalization in `Chain::new` (finding 1).

### L2 — no dead id in a cheap chain (E5-M2)
1. **Precise?** Yes, and deliberately scoped to "cheap chain" — the scope is
   load-bearing (see 2). `is_dead` is substring-based and the statement says
   "contains": consistent.
2. **Mechanism sufficient?** Yes on the cheap route: `status()` generates all
   three dead markers, `registry_for` pairs them to catalog refs cyclically,
   and the assertion checks the emitted entries. Probe D shows the other
   side: `tier:mid` on a FANTASMA-stamped default returns `Ok` with
   `id_status: "FANTASMA"` — by design the consumer (shell FANTASMA
   case-loop) gates those routes. A reader of the one-line statement will
   not know that; amendment promoted (finding 4).
3. **Incident closed?** Yes for the route the incident ran on: fixture
   catalog carries `ghost-model:free` (FANTASMA) and vector
   `cheap_with_openrouter_credential` pins it to `skipped`; `cheap_all_dead_is_loud`
   pins the zero-live exit. Pre-gate code would have served it first.
4. **Type or test?** An `IdStatus` parse type could make Dead unrepresentable
   in a *chain entry*, but the gate's action is skip-with-WARN, not reject —
   the type cannot express "skip". Keep as test; candidate all-routes law
   promoted to "Not laws (yet)".

### L3 — cheap order keyless → context desc → ref asc, pure (E5-M4/R1)
1. **Precise?** The order triple is precise; "pure function of catalog
   content" is stated as determinism. Two unstated conventions promoted as
   addendum: `context_length: null` orders as 0, empty-`ref` entries are
   dropped — both match Python `_catalog_order` (`-(m.get("context_length") or 0)`,
   `m.get("ref")` truthiness).
2. **Mechanism sufficient?** Yes with one caveat: `l3_cheap_order` re-derives
   the key with an expression textually identical to the implementation's —
   a wrong key copied into the test would stay green. The concrete anchor is
   vector `cheap_with_openrouter_credential` (keyless pair first, then
   262144 > 256000). Determinism is exercised only against the reversed
   input, but the generator randomizes 0–12 models per run. The P1.md
   "differential check vs Python (2026-09-19, 11 refs)" is a dated manual
   claim, not an automated mechanism — T03's job to automate.
3. **Incident closed?** Yes: R1's zero-key-first promise is exactly the first
   sort key, and the vector pins it on data with both legs present.
4. **Type or test?** Ordering is a function property; no type applies.

### L4 — non-keyless needs a file credential; env never an input (E5-M5)
1. **Precise?** No — two problems. Domain: unstated (which routes?). And the
   main clause is violated by a reachable case: a catalog entry with
   `keyless: false` and provider `null` enters the chain with no credential
   (probe C); "its provider has a file credential" has no referent there.
   The proptest mirrors the hole — `if let Some(p)` skips the assertion
   exactly when the provider is unknown (the spec's "assertion inside a
   branch that might never execute" trap). Promoted: amended statement
   ("with a known provider") + decision D3 + pinning vector
   `cheap_keyed_unknown_provider_passes_gate`.
2. **Mechanism sufficient?** For known providers, yes: creds generator is
   0–3 of {opencode, openrouter}, keyed entries with unknown creds are
   generated and asserted. The "environment is never an input" clause is
   enforced structurally (`Inputs.credentials` is the only credential
   input; no env read in `src/`), i.e. by code shape, not by any mechanism —
   flagged for the P2 grep gate (finding 5).
3. **Incident closed?** Yes where it bites: vector `cheap_zero_key_only`
   (zero creds → keyed legs skipped, keyless leg survives); the D5
   poisoned-env leg covers the shell side. The Rust has no "pre-fix" state —
   it is the port; the vector is the pin.
4. **Type or test?** Yes, cheap: `enum Keyless { Zero, Keyed(Provider) }`
   makes "keyed without a provider" unrepresentable and simultaneously
   expresses D2's tri-state. Proposed in D3/could-list.

### L5 — free route never yields outside-allowlist; citation is a violation (E5-M6/R4)
1. **Precise?** Statement broader than mechanism in one reachable corner:
   the dead-id gate runs before the allowlist check, so a **dead** ref
   citing an outside provider is skipped as DeadId — probe B returns
   `NoLiveRef`, never `ProviderOutsideAllowlist`. Amendment promoted: "a
   **live** catalog entry citing…". Precedence itself is sensible (dead refs
   are already loud via WARN) but it is a decision, now written down.
2. **Mechanism sufficient?** Yes for live intruders at any position
   (`l5_outside_allowlist_is_a_violation` inserts at idx 0–5, statuses
   EXISTE). The dead-intruder interplay is unreachable in the proptest:
   `provider()` only generates allowlisted names, so the L2-block never sees
   an outside provider. Noted, not fixed (would need a src change to alter).
3. **Incident closed?** Yes for the kernel: vector
   `cheap_provider_outside_allowlist_is_loud` pins tampered-catalog → error.
   But the *live* path enforcement story is split (see Review item 5/D1):
   Python passes through; shell marks violado post-hoc. The incident-class
   gate the Fable verified (M6 "allowlist adulterada→violado provado por
   perna do gate") is `test-free-path.sh` leg 8 — closed there.
4. **Type or test?** Allowlist as a set type adds nothing; the policy
   question (R4: default allowlist is an explicit owner dial) is already
   answered by `data/free-provider-allowlist.json`. Keep as test.

### L6 — never empty, typed failures, no catalog ⇒ CatalogMissing (E5)
1. **Precise?** Third clause needs its scope stated: it is the *free route*.
   `tier:expensive` with no catalog resolving via stamped defaults is the
   e82f008 contract (vector `expensive_outside_catalog_typed_unknown_provider`);
   `direct` ignores the catalog. Amendment promoted.
2. **Mechanism sufficient?** `l6_no_catalog_never_defaults` quantifies over
   registries 0–5 and asserts the exact typed error — good. The
   "`Chain::new` rejects empty" clause has no named test anywhere in
   `tests/laws.rs` (indirectly: the L2-block asserts non-empty output). The
   type makes it near-unreachable (`entries` private, `new` is the only
   constructor); still cheap to pin — noted (finding 6).
3. **Incident closed?** Yes: the E5 default (`deepseek-v4-flash-free`, dead
   hint served first) is exactly what `CatalogMissing` refuses; Python
   `_resolve_tier_cheap` mirrors it (exit 2, "Recusando cair nos defaults").
   Incident input (no readable catalog) → old code served a default, both
   implementations now exit loud.
4. **Type or test?** Already the best kind of type: private `entries` +
   fallible constructor. This is the model L4's tri-state should follow.

### L7 — gates filter, never reorder (design, no incident)
1. **Precise?** Yes: cheap chain is a subsequence of `catalog_order(catalog)`.
2. **Mechanism sufficient?** Yes: cursor-based subsequence over the
   independently recomputed order; invented or reordered refs fail, and
   duplicate refs cannot bypass the cursor. Honest "(design, no incident
   yet)" — good hygiene.
3. **Incident closed?** n/a (stated as none).
4. **Type or test?** Filter-preserves-order is provable by construction; a
   type would be ceremony. Keep as test.

## Review items 5–8

**5. `ProviderOutsideAllowlist` vs Python (violation vs pass-through).** Gap,
promoted as decision D1. The divergence was recorded nowhere an operator
greps: `P1.md` had the law but not the divergence; the CLI message
(`lib.rs` Display: "fora da allowlist (E5-M6/R4) — sync comprometido") names
the incident but not the Python/shell difference; the spec
(`DECISIONS-E6`) records M6 as the post-hoc `violado` gate only. Today's
enforcement map: kernel = pre-dispatch exit 2; `resolve-tier` = pass-through
(no allowlist code at all); live shell = `ledger-finalize.sh:136–151` marks
the run violado after the fact. An operator whose dispatch suddenly exits 2
after a catalog sync now has one place to look: `P1.md` D1.

**6. `direct()` stamps `keyless: true` for every entry.** It is a lie the
wire tells the shell: a consumer applying the run-with-fallback rule
(`[ "$KEYLESS" != "1" ] && [ -n "$PROVIDER" ]` → credential gate) concludes
"no credential needed" for legs that were never gated — e.g. vector
`direct_id_with_fallback_and_statuses` emits `provider: deepseek, keyless: true`.
Promoted as decision D2 (documented "not applicable" semantics + tri-state
proposal `Keyless | Keyed(provider) | Ungated`, which is the same enum D3
needs). Chose documentation over a src change: T09 is read-only and the
tri-state alters the wire contract (`parse_us` arity/values), which is T06/
owner territory.

**7. `single_tier_id` port — branches not replicated / added.**
Not replicated (all verified dead or unreachable in the Python, so omissions
are correct):
- the Python's dead `tier == "cheap"` block *inside* `if models:`
  (`lib-oracfit-mode-loader.py:541–554`, deepseek-v4-flash-free /
  flash-openrouter / "mais barato" search) — unreachable because the outer
  `if tier == "cheap"` already exited via `_resolve_tier_cheap`;
- `_TIER_FALLBACKS` (`:49–53`) — dead: `_DEFAULT_TIERS` covers the same
  three tiers, so `fallback` is only consulted when `default` is falsy,
  which never happens (and vision's fallback is `None` anyway);
Rust additions (kernel absorbed shell duties):
- the `tier:` prefix is *required* (`strip_prefix`); Python `removeprefix`
  is optional, so a bare `"cheap"` is a tier route in Python but falls to
  `direct()`/`UnknownModel` in Rust (the shell only ever sends `tier:*` —
  latent, noted);
- catalog metadata enrichment (provider/keyless), the E5-M5 credential gate
  (`EmptyAfterCredentialGate`), and `id_status` stamping on the resolved id —
  the Python prints a bare id and `run-with-fallback.sh` does that work;
- type strictness: registry `tier`/`best_for` of the wrong JSON shape fail
  the whole Rust parse (loud) where Python's duck typing would just not
  match (e.g. `"x" in "x e y"` substring behavior on a string `best_for`).

**8. "Not laws (yet)" candidates — statement + cheapest mechanism** (promoted
into `P1.md`): (a) paid-tier candidate narrowed to "`expensive`/`vision`
never resolve to a registry `tier: free` model" — the original wording
("a paid tier never resolves to a free-only provider") is falsified by the
port itself, since mid's best_for rule deliberately accepts `free`
(`tier in ("paid","free")`); mechanism: proptest with a free-only match,
assert fall-through to the stamped default. (b) direct-path candidate: noted
that until D2's tri-state lands, the candidate is vacuous (`keyless: true`
everywhere); mechanism: L2-block style assertion extended to direct
(`Keyed(p)` ⇒ credential present).

## Findings

1. **gap (L1)** — `Chain::new` accepts `provider: Some("")`; `render_us`
   emits the empty field and `parse_us` returns `None`: the round-trip law
   does not hold on a constructible value, and the L1 generator (min-length
   1) cannot produce it. Unreachable from `resolve()` today, reachable by
   any lib consumer. Repro: probe A above. Promotion: amendment + proposed
   mechanism (normalize/reject empty provider in `Chain::new`).
2. **gap (L4)** — cheap-chain entry with `keyless: false`, provider `null`
   passes the credential gate (mirrors the shell's `-n "$PROVIDER"` guard);
   statement and proptest both skip the case. Repro: probe C. Promotion:
   decision D3 + vector `cheap_keyed_unknown_provider_passes_gate` +
   tri-state proposal.
3. **gap (L5)** — dead ref citing an outside-allowlist provider is skipped
   (DeadId), not raised as a violation; "a catalog citing one is a violation"
   is broader than the mechanism. Repro: probe B. Promotion: amended
   statement in `P1.md` ("live entry").
4. **gap (L2/L6 statement scope)** — `tier:*`/direct routes emit
   dead-stamped entries by design (probe D) and L6's CatalogMissing clause is
   free-route-only; neither scope was written down. Promotion: amendments +
   all-routes candidate law in "Not laws (yet)".
5. **gap (operator docs, item 5)** — the kernel-stricter-than-Python
   allowlist decision existed only in code and a go-live doc. Promotion:
   decision D1 in `P1.md`.
6. **note (L4/L6 mechanism)** — "environment is never an input" is
   structural, not test-enforced; `Chain::new`-rejects-empty has no named
   test. Both flagged for the P2 CI/grep gate; recorded in amendments.
7. **note (L3 mechanism)** — `l3_cheap_order` re-derives the sort key with
   the implementation's own expression (copy-paste risk); the concrete
   vector is the semantic anchor; determinism exercised only against the
   reversed permutation. Accepted as sufficient given the vector + T03.
8. **note (L1 positive result)** — suspected CR round-trip failure refuted
   by probe: `lines()` strips only a CR adjacent to LF, and the typed
   `keyless` bool renders last. The typed-in-last-position property is now
   recorded in the amendment ("do not reorder the four wire fields").
9. **note (port, item 7)** — dead Python branches (`cheap`-in-models block,
   `_TIER_FALLBACKS`) correctly omitted; Rust adds prefix-strictness,
   metadata enrichment, credential gate and type strictness. Listed above
   for the port ledger; no action.
10. **note (docs)** — `P1.md` referenced a nonexistent `kernel/laws/README`;
    fixed in place on this branch, `LAWS.bend` sentence kept with a
    forward pointer.

Ranked proposed changes — **must**: none (no wrong output reachable from
`resolve()`; kernel matches the shell it replaces on every divergence
found). **should**: (1) fold the amendment statements into the law table;
(2) normalize/reject `provider: Some("")` in `Chain::new` (one line, closes
finding 1); (3) tri-state `keyless` (closes D2 lie and D3's hole at once —
pairs naturally with T06-class mutation work). **could**: (4) one-line
`Chain::new(vec![])` pin test; (5) P2 grep gate for "no env read in
`src/`"; (6) `IdStatus`/`Keyless` newtypes per D3.
