## Findings

1. **note** (design divergence; touches L1's wire framing, not its
   statement): an unknown `--format` value (`xml`, `jsn`, `""`, `JSON`)
   silently renders the US wire format with exit 0, while the `main.rs`
   doc comment advertises `[--format us|json]` only. Deterministic and
   byte-compatible for the shell consumer, so recorded as a decision, not
   a bug. Repro: `dispatch-policy resolve tier:cheap … --format xml`
   → exit 0, US output. Promoted as **D1** in `kernel/laws/P1.md`
   Decisions.
2. **gap** (no law touched): the shared vector schema `p1-vectors/1` can
   only express resolution semantics, so the whole CLI contract (exit
   codes 0/2/3, usage text, stdout-empty-on-failure, wire framing) had no
   permanent mechanical home — it lived only in this spec's checklist.
   Closed by promoting `cli_*` tests into `tests/laws.rs` that run the
   real binary (`CARGO_BIN_EXE`) against fixtures read from
   `kernel/vectors/p1/cases.json`; the exit/stdout property is also
   filed under "Not laws (yet)" as a candidate law.
