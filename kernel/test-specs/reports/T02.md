# T02 — Do the shipped tests test what they claim?

## Verdict: FAIL

The vector harness is honest (both tamper oracles caught the tamper and
named the case) and law/vector coverage is 100 % as claimed — but the L3
law test is **not** honest as a universal claim: at `PROPTEST_CASES=5000`
`l3_cheap_order` fails 3/3 runs with a shrunk counterexample, and even at
the shipped default of 256 cases the laws binary is a ~20 % coin flip.
The suite was green in step 1 by luck of the per-process seed, not by
strength. Promoted: 2 vectors, 1 P1.md Decisions row, 1 Not-laws row,
1 BENCH block.

### Step 5 — proptest volume

```
$ for i in 1 2 3; do PROPTEST_CASES=5000 cargo test --release --test laws ...
test result: FAILED. 5 passed; 1 failed   (run1 wall 458 ms, run2 474 ms, run3 466 ms)
```
Failing test every time: `l3_cheap_order`, shrunk input:

```
assertion `(left == right)` failed at laws.rs:92 (reversal determinism)
left:  [ref "1" provider None        keyless false ctx None,
        ref "1" provider Some("opencode") keyless false ctx None]
right: [ref "1" provider Some("opencode") keyless false ctx None,
        ref "1" provider None        keyless false ctx None]
```
Root cause: the L3 sort key `(!keyless, Reverse(ctx), ref)` is not a
total order when two models share `(keyless, ctx, ref)` (duplicate
refs); `sort_by_key` is stable, so FILE order decides the tie and
reversing the file reverses the chain — "pure function of catalog
content" is false for such catalogs. Two aggravating mechanics found:

```

$ # with the file present: 12/12 default runs red (permanent replay)

$ for i in 1..10: cargo test --release --test laws --quiet

```

## Findings

1. **bug** (law L3) — `l3_cheap_order` fails at `PROPTEST_CASES=5000`
   (3/3) and the default 256-case run is red ~20 % of the time (2/10):
   the L3 determinism clause does not hold for catalogs with duplicate
   `(keyless, context_length, ref)`; stable sort makes output depend on
   file order. Additionally, once proptest persists the counterexample
   to `tests/laws.proptest-regressions`, every subsequent run replays it
   and the suite is permanently red until the file is removed — the
   README's mechanical oracle (`cargo test` exits 0) is therefore flaky
   on main as shipped. Promoted: vector
   `T02_l3_duplicate_ref_ties_keep_file_order` + "Not laws (yet)" row
   with candidate mechanisms + BENCH rows.
2. **gap** (law L4) — a `keyless: false` catalog entry with `provider:
   null` bypasses the credential gate entirely and enters the cheap
   chain; on the wire it renders `provider ""` + `keyless 0`, which the
   shell cannot gate. Consistent with the typed-unknown decision
   (e82f008) but never stated. Promoted: vector
   `T02_keyed_entry_unknown_provider_skips_credential_gate` + P1.md
   **Decisions** row.
3. **note** (no artifact; does not count per README rule 1) — error
   vectors compare only the serialized variant tag; payload fields
   (`request`, `ref`, `provider`, `tier`) are unpinned, so a regression
   that keeps the variant but corrupts the detail would stay green.
4. **gap** on the step-6 oracle — `EmptyAfterCredentialGate` is reached
   by only 2.2 % of generated inputs (target ≥ 5 %, gap bar < 1 %): the
   E5-M5 error shape is exercised, but thinly. Reported per spec; no
   artifact (below the gap threshold the spec defines).
5. **note** — proptest prints `FileFailurePersistence::SourceParallel
   set, but failed to find lib.rs or main.rs` on every run, yet the
   regressions file IS written next to the test source; the warning is
   misleading about where the file lands. Promoted as one sentence in
   P1.md "Rule for this directory".
