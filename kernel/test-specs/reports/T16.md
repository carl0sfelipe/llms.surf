# T16 — Dedup law (L8) — report

## Verdict: PASS

Law L8 ("a chain never contains the same ref twice; the first occurrence in
`catalog_order` wins") is implemented, universally quantified by a proptest,
pinned by a vector, and recorded as a Decisions row with the deliberate
divergence from Python. Mechanical oracle green (`cd kernel && cargo test
--release` exit 0; `l3_cheap_order` flake documented below — pre-existing on
pristine `main`, see Finding 1).

## Findings

1. **[bug] (L3) `l3_cheap_order`'s determinism assertion can fail on full
   sort-key ties, and one organic red poisons every later run.** Minimal
   failing input (shrunk, captured this session):
   `cat = [{ref: "/", provider: Some("opencode"), keyless: false,
   context_length: None}, {ref: "/", provider: None, keyless: false,
   context_length: None}]` — the sort key omits `provider`, so a full tie
   keeps file order under the stable sort, and the `shuffled == first`
   assertion fails. Observed organically ~1 in ~20 full-suite rounds on
   this machine; measured 14/15 green on the branch and 15/15 on pristine
   `main` @ `1425b9c` in independent rounds. **The operational hazard is
   bigger than the flake itself:** proptest persists the failing seed in
   the untracked `kernel/dispatch-policy/tests/laws.proptest-regressions`
   and replays it before any novel case, so after one organic red every
   subsequent run is red — on any branch, including pristine `main` code —
   until the file is deleted (a first control run here measured "12/12 red
   on main" that was pure replay contamination; corrected above). The file
   is deleted before the final oracle run and is **not committed**; if the
   battery keeps hitting this, the fix belongs to L3 (add `provider` or
   input order to the key, or drop the shuffle assertion for ties), not to
   L8. Not caused by L8 (`catalog_order` is untouched).
2. **[gap] (L8) Deliberate divergence from Python, and its relation to the
   wave-1 branches.** Python `_catalog_order`/`sorted` keeps both duplicate
   legs (parity pinned by `T05_duplicate_ref_keeps_both_legs` on `p1-T05` —
   superseded on this branch); T03's Decision of 2026-09-19 (per-occurrence
   gating, `p1-T03`) is narrowed: gating stays per-entry, selection is
   per-ref, so a duplicate can no longer rescue a dead/uncredited first
   occurrence. `p1-T03`'s vectors `T03_duplicate_ref_gate_is_per_occurrence`
   and `T03_duplicate_ref_shell_exit2_rust_still_ok` pin the superseded
   behaviour and must be re-pinned when that branch rebases. The T03 harness
   lives outside the repo (`/tmp/t03/harness.py`), so its exclusion-list
   obligation is recorded here and in `kernel/laws/P1.md` (Decisions
   2026-09-19): duplicate-ref inputs move to the exclusion list, with the
   divergence noted. Why the divergence is accepted: retrying the same ref —
   possibly the same dead ref — twice is the E5 smell.
3. **[note] (L8 × L3 tie interaction).** For full sort-key ties (same
   ref/keyless/context, differing only in `provider`), "first occurrence"
   is file order via the stable sort — deterministic per catalog file, which
   is what dispatch needs, but not permutation-invariant (exactly Finding
   1's tie class). The proptest draws contexts from `0..4` so L8 is
   exercised under frequent ties; `l8` was green 10/10 rounds while `l3`
   flaked — L8 adds no flakiness.
4. **[note] Dedup precedes the gates on purpose.** With a dead first
   occurrence and an alive duplicate, the chain gets neither (the duplicate
   is `DuplicateRef`, the first is `DeadId`; if it was the only ref,
   `NoLiveRef`). This is the point of the law; a design where the alive
   duplicate survives would re-open the E5 retry smell and was rejected.
