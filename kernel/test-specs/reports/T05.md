# T05 — Malformed inputs

Branch `p1-T05`, kernel `dispatch-policy` @ `1425b9c`. Binary built once
(`cargo build --release`), every case below is a JSON fixture pair + one
`dispatch-policy resolve` command. Baseline before any case:
`cargo test --release` → 6 laws + 1 vector test, all ok. Scratch fixtures in
`/tmp/p1-T05-tmp` (not committed); promoted artifacts are in this branch.

## Verdict: PASS

No panics anywhere; no silently wrong chain. Every garbage input produced a
typed, loud error (`PolicyError` variant or exit 3 serde error). Four
divergences from the spec's stated expectations found and promoted as
`gap` (findings 1, 2, 4, 5); none justified FAIL because the terminal
behaviour in every case stayed typed + loud + non-silent.

## Findings

1. `gap` (registry; law L6-adjacent) — `"models": null` is **exit 3 parse
   error**, not an empty registry: serde `#[serde(default)]` covers absence
   only. Spec said "expect parse error exit 3 **or** empty; record which".
   Recorded: parse error. Promoted as a Decisions row; empty-registry half
   pinned by `T05_empty_registry_cheap`.
2. `gap` (registry; laws L1/L6) — direct request `""` with a registry entry
   missing `id` yields `MalformedField { field: "ref" }` exit 2, **not**
   `UnknownModel`/usage as the spec expected. The safety property held
   ("never a chain with an empty ref"), the typed error just names the field
   instead of the lookup miss. Pinned by `T05_direct_empty_id_is_malformed_not_chain`
   + Decisions row.
3. `note` (registry) — duplicate ids: **last** `id_status` wins
   (`status_map` BTreeMap last-write), byte-deterministic across runs
   (FANTASMA last → NoLiveRef exit 2; EXISTE last → chain). Pinned by
   `T05_duplicate_id_last_status_wins` + Decisions row.
4. `gap` (catalog; law L6) — catalog **parse** errors are NOT exit 3: the
   shell demotes them to WARN "tratado como ausente" → `CatalogMissing`
   exit 2 (C10–C12: string `keyless`, `-1`, `1e6` are all rejected by serde,
   as the spec wanted — only the exit code differs). A tampered catalog is
   indistinguishable from an absent one at the exit-code level. Promoted as
   a Decisions row (kept: loud either way; exit-code split is a candidate
   contract change, T04 territory).
5. `gap` (catalog; law L5) — **provider `""` divergence, confirmed**: Rust
   treats `Some("")` as a real provider → allowlist check fails →
   `ProviderOutsideAllowlist` exit 2 even with every credential present.
   Shell tree (`run-with-fallback.sh`) does `m.get("provider") or ""` →
   falsy → the `[ -n "$PROVIDER" ]` credential gate is skipped entirely, so
   the keyed leg passes ungated and `provider_efetivo` becomes `""`. Rust is
   the louder side; unreachable on synced data (`sync-free-catalog.sh`
   asserts provider ∈ {opencode, openrouter}). Pinned by
   `T05_empty_provider_is_allowlist_violation` + Decisions row.
6. `gap` (catalog; candidate law) — same `ref` twice (different `keyless`)
   → **both** legs enter the chain; Python `sorted` keeps both too (parity
   confirmed). Dedup is a candidate law with no stated rule yet →
   "Not laws (yet)" row + `T05_duplicate_ref_keeps_both_legs`.
7. `note` (allowlist; law L5) — allowlist matched **verbatim**: `"openrouter "`
   (trailing space) does not cover `"openrouter"` → violation exit 2;
   duplicates harmless (BTreeSet). Pinned by `T05_allowlist_whitespace_not_trimmed`.
8. `note` (allowlist; law L5) — the allowlist check applies to
   `Some(provider)` even on **keyless** entries; with `providers: []` only a
   keyless+`provider: null` entry chains. Pinned by
   `T05_empty_allowlist_keyless_providerless`.
9. `note` (registry) — L1b bites end-to-end at the CLI: ref containing
   `\x1f` or `\n` → `MalformedField` exit 2, stdout empty (C14/C15). Pinned
   by `T05_ref_with_us_delimiter_is_malformed` /
   `T05_ref_with_newline_is_malformed`.
10. `note` (registry) — `cli_hints` with nested objects/numbers parses and
    never aliases (only string values alias); request still resolves by id.
    Pinned by `T05_cli_hints_non_string_ignored`.
11. `note` (credentials) — `--credentials` naming a provider outside the
    allowlist: no effect, no error (C19). Evidence-only.
12. `note` (registry) — as-expected typed door rejections, exit 3: numeric
    `id_status`, non-string `fallback`, 0-byte file (EOF), UTF-8 BOM
    (serde_json rejects BOM; the shell tree writes no BOMs). Covered by the
    first Decisions row.
