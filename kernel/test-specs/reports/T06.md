# T06 — Mutation: do the laws bite?

## Verdict: PASS

13 of 15 spec mutations are killed by the shipped tests. The two survivors
are exactly the ones the spec allows: **M9** (marked "expect survival") and
**M12** (explained as a gap, promoted test). Post-promotion re-run kills
both, so the suite now bites on 15/15 (M12 counted once, both variants
killed). One mutation that survives *and* corresponds to a law in `P1.md`
was found: M12 vs **L6** — reported as a `bug` in the test suite (high) and
closed with a promoted law test in this same branch.

Total wall-clock: **13 min** session (budget 60 min). Full battery itself:
cold baseline 11.7 s + 16 mutations x ~4 s = 65.1 s wall (`--no-fail-fast`
pass). Recorded in `kernel/BENCH.md`.

Method: worktree `p1-T06`, scratch copy `cp -r kernel /tmp/t06-kernel`
(never committed; `src/` restored from a pristine copy after every
mutation and byte-identical at the end). Each mutation is a literal string
replacement on `src/lib.rs` applied by a Python harness that fails loudly
unless the pattern matches exactly the expected number of times. Tests run
with `cargo test --release --no-fail-fast` so *all* killer binaries are
seen (plain `cargo test` stops at the first red binary and under-reports
killers, e.g. M3's vector kill).

## Findings

1. **bug (high) — L6** — M12a+M12b: both `Chain::new` guards ("reject empty
   entry list", "reject empty `ref`") were dead code: deleting either kept
   the entire shipped suite green (`*_is_loud` vectors never construct such
   chains; the laws' `field()` strategy generates non-empty strings only).
   `P1.md` L6's mechanism literally claims "`Chain::new` rejects empty" — a
   law that existed on paper only. Repro: harness M12a/M12b, output above.
   Closed by promoted `l6_chain_new_rejects_empty` (both routes, including
   `parse_us("")`).
2. **gap — L4** — M9: a fallback to `std::env::var(p)` inside the cheap
   credential gate survives every shipped test, as the spec predicted — no
   test observes the environment. Proposed mechanism implemented as
   `l4_env_is_never_an_input`: set env vars named after both providers,
   assert the keyed ref is still gated out (and a keyed-only catalog still
   yields `EmptyAfterCredentialGate`). This kills M9.
3. **gap — L2** — M4-adjacent vector coverage: `DEAD_ID_STATUSES` has three
   members, but the shared vectors (the Bend-lab door) pinned only
   `FANTASMA`. Narrowing `is_dead` to a single non-FANTASMA status is
   invisible to every vector and caught only by the sampled proptest.
   Promoted vector `T06_nao_statuses_are_dead` pins `NAO-ENCONTRADO` and
   `NAO-VERIFICADO` skips and now kills M4 alongside the law.
