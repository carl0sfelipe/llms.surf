## Findings

- Normalization lives in `empty_provider_is_none` (`deserialize_with`)
  applied to all three `Option<String>` provider fields — `RegistryModel`,
  `CatalogModel`, `ChainEntry` — so the invariant "provider is never
  `Some("")`" holds on every parse path (JSON inputs and wire
  round-trip; `parse_us` already mapped `""` → `None`). Whitespace-only
  strings (`" "`) are deliberately NOT normalized: Python treats them as
  truthy, so exact producer parity is preserved.
- T03's harness: never promoted (wave-1 branches not merged; it lived in
  `/tmp/t03/harness.py`, outside the repo). Nothing in-tree to re-run;
  the vector now pins the §16 input mechanically, so any future
  differential harness sees Rust/Python parity on this case by
  construction.
- `cargo fmt --check` fails on **main** already (pre-existing, e.g.
  `src/lib.rs:137`, `tests/laws.rs:2`, `tests/vectors.rs:46` under the
  current rustfmt) — untouched here; flagged for T12, whose CI gate
  `fmt --check` would be red on day one without a format pass.
- `l3_cheap_order` proptest (known ~20% tie flake on main) passed on all
  3 runs in this task; no flake observed, nothing fixed.
