## Findings

1. **bug** (law L3) — `tests/laws.rs::l3_cheap_order` is red on main @
   `1425b9c`, before any T10 change. `catalog_order` claims to be a pure,
   order-independent function of catalog content, but its sort key
   `(!keyless, Reverse(ctx), ref)` ties on entries equal in all three
   fields and differing in `provider`; the stable sort then preserves
   input order, so reversing the input reverses the output and the
   determinism assertion (laws.rs:92) fails. Repro: `cd kernel && cargo
   test --release` (10/10). Minimal input committed as
   `kernel/dispatch-policy/tests/laws.proptest-regressions`. Candidate
   mechanisms (owner's call, not fixed here): tie-break on `provider`, or
   a typed unique-ref invariant on catalogs. The vectors cannot catch this
   (no duplicate-ref case exists); the proptest did its job.
2. **gap** (docs; touches L3/"Not laws") — the `mid`/`expensive`/`vision`
   registry-first preference chains and the stamped defaults (mid →
   `deepseek-v4-pro`, expensive → `claude-sonnet-5`, vision →
   `gemini-3.6-flash`, `id_status: ""`) exist only in `src/lib.rs`
   (`single_tier_id`). P1.md calls them "a faithful port" but states no
   rule; a docs-only implementer (the Bend lab) guesses wrong, proven by
   proposed vectors 2 and 3. Promoted: §"Cross-implementation contract"
   in `docs/research/specs/P1-dispatch-policy-rust.md`.
3. **gap** (law L5/L2) — L5 says "a catalog **citing** [an outside
   provider] is a violation", but the mechanism checks the allowlist
   after the dead gate, per entry: a dead id citing `paidcorp` is skipped
   as `DeadId` and never raises `ProviderOutsideAllowlist` (proposed
   vector 4: expect `NoLiveRef`, verified). Law statement overpromises;
   either the statement or the mechanism should change. Promoted as a
   contract sentence + P1.md note.
4. **gap** (docs; L3/L7) — `skipped` ordering is under-pinned: the single
   vector exercising it (`cheap_zero_key_only`) is satisfiable by two
   different rules (reason-grouped, which I inferred, vs `catalog_order`
   encounter order, which the code does). They diverge on any catalog
   where a no-credential entry sorts before a dead one (proposed vector
   1). Promoted: contract sentence.
5. **gap** (docs) — `P1-dispatch-policy-rust.md` has no `PolicyError`
   variant list; T10 step 6 had to read the crate to close the schema.
   Also `MalformedField` (L1b) is exercised by no vector at all — the
   vectors cannot see the delimiter law. Promoted: variant list in the
   contract section; vector addition for MalformedField left as a
   suggestion (would need a catalog ref containing US, which the vectors'
   `expect.error` string form can express).
6. **note** (law L4) — a keyed catalog entry with `provider: null` passes
   the allowlist check and the credential gate (no provider to deny);
   code-only rule, unpinned. Contract sentence promoted.
7. **note** — the tier route takes catalog metadata when the resolved id
   is in the free catalog, including the credential gate, so a tier can
   end in `EmptyAfterCredentialGate` (proposed vector 5). Code-only,
   unpinned. Contract sentence promoted.
8. **note** — direct path details a second implementer must copy:
   `cli_hints` aliases apply only there (cheap route matches ids
   exactly); no dead/credential/allowlist gate on that path; a `fallback`
   id absent from the registry still emits an entry (`id_status: ""`,
   provider `null`); `is_dead` is substring containment (this half L2
   does state). Contract sentences promoted.
9. **note** — portability score 13/13 at step 4. The 13 vectors constrain
   only what they exercise: 5 of my 9 code-only inferences were wrong in
   general while still passing every vector. Expected shape of the score:
   the vectors are necessary but not sufficient as a cross-implementation
   contract until proposed vectors 1–5 land.
