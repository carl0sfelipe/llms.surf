# Laws — P1 dispatch policy

A law is: **id · statement · incident it closes · mechanism that checks it**.
A law without a mechanism does not belong here (see the "Rule for this
directory" section at the bottom of this file — T09, 2026-09-19: the
former `kernel/laws/README` pointer was dangling; no such file exists).
The Bend lab mirrors this file as `LAWS.bend` (to be generated; see
`docs/research/direction-kernel-rust-bend-lab-2026-09-19.md`).

| Law | Statement (∀ inputs) | Incident | Mechanism |
|---|---|---|---|
| L1 | Chain fields are typed; the wire format `render_us`/`parse_us` round-trips exactly and a field containing a delimiter cannot become a chain | `e82f008` (TSV read keyless flag as provider "1") | type `ChainEntry { provider: Option<String>, keyless: Option<bool> }` (tri-state: `1` zero-key, `0` keyed, `-` gate not applicable); `tests/laws.rs::l1_us_wire_roundtrip`, `l1b_delimiters_are_rejected` |
| L2 | No entry whose registry `id_status` contains FANTASMA / NAO-ENCONTRADO / NAO-VERIFICADO ever appears in a cheap chain | E5-M2 | `l2_l4_l5_l6_cheap_gates`; vectors `cheap_with_openrouter_credential`, `T06_nao_statuses_are_dead` |

## Statement amendments (T09 law review, 2026-09-19)

Proposed precise wordings; the table keeps the short forms until the owner
folds them in. Each was checked against the mechanism by probe, not prose.

- **L1** — proposed statement: "∀ chains: `parse_us(r, render_us(c)) == c`;
  constructing a chain whose `ref`/`id_status`/`provider` contains US or LF
  (or whose `ref` is empty) fails with `MalformedField`." Verified by probe:
  a field containing CR survives the round-trip because the typed `keyless`
  bool renders last — do not reorder the four wire fields. Residual hole:
  `provider: Some("")` builds, renders as the empty field and parses back as
  `None` — the L1 generator (min-length-1 fields) cannot produce it, so the
  round-trip law does not bite there. Proposed mechanism: `Chain::new`
  normalizes (or rejects) an empty-string provider.
- **L2** — scope note: this law is cheap-route-only **by design**;
  `single_tier`/`direct` emit dead-stamped entries (probe: `tier:mid` on a
  FANTASMA-stamped default returns `Ok` with `id_status: "FANTASMA"`) and
  delegate the skip to the consumer, mirroring the shell's FANTASMA
  case-loop. Candidate law once the kernel replaces the shell: "no
  dispatched ref carries a dead id_status on any route"; mechanism: extend
  the door gate to `single_tier`/`direct`.
- **L3** — addendum: `context_length: null` orders as 0 and empty-`ref`
  catalog entries are dropped; both match Python `_catalog_order`
  byte-for-byte.
- **L4** — precise domain: "a non-keyless entry **with a known provider**
  appears only if…"; the unknown-provider keyed case is decision D3 (T09). The
  "environment is never an input" clause is structural (`Inputs.credentials`
  is the only credential input; no env read in `src/`), not test-enforced —
  a grep gate belongs in the P2 CI check.
- **L5** — precedence: the dead-id gate runs **before** the allowlist check,
  so a dead ref citing an outside provider is skipped (DeadId), not raised as
  a violation (probe: such a single-entry catalog yields `NoLiveRef`, not
  `ProviderOutsideAllowlist`). Proposed statement: "a **live** catalog entry
  citing a provider outside the owner allowlist is a violation, not a skip".
- **L6** — the third clause is free-route-scoped: `tier:<other>` without a
  catalog resolves via stamped defaults (that is the e82f008 contract), and
  `direct` ignores the catalog. The "`Chain::new` rejects empty" clause is
  enforced by the type (private `entries`), not by any named test — cheap to
  pin with a one-line test in `tests/laws.rs`.
- **L7** — no amendment; the subsequence assertion is cursor-correct and
  duplicate refs cannot bypass it.

## Rule for this directory

`kernel/laws/<pillar>.md` lists every law of that pillar with its mechanism.
CI check (to add with P2): every `L\d+` id in this file must appear in
`kernel/dispatch-policy/tests/` or `kernel/vectors/`. Presence-only, like
the AGENTS.md grep in bestmodel S25c — content honesty stays human.
Run byproduct: a red proptest writes `tests/*.proptest-regressions`
(next to the source) and replays it on every later run, so one discovered
counterexample turns the suite permanently red until the file is removed;
never commit it while the law it pins is still failing (T02).

  `kernel/test-specs/DECISIONS-wave1-2.md`): L3's determinism clause ("pure
  function of catalog content") held only for catalogs with distinct
  `(keyless, context_length, ref)` triples — the stable sort leaked FILE
  order for duplicate refs (`laws::l3_cheap_order` red at
  `PROPTEST_CASES=5000`, ~20 % of plain runs; T02). Resolution: L8 (T16)
  adopted as a precondition of L3 — `catalog_order` sorts by the key, then
  dedupes by `ref` keeping the first (= best-ranked) occurrence; L3
  restated in the table above. The full-tie behaviour stays pinned at
  vector level by the re-pinned `T02_l3_duplicate_ref_ties_keep_file_order`.
- (RESOLVED 2026-09-19 by **D-L3**, same decision): the "byte-deterministic
  pure function" falsification by full-key ties (same keyless/context/ref,
  different provider; counterexample was pinned in
  `kernel/dispatch-policy/tests/laws.proptest-regressions`, T08/T10 —
  the file was removed with this decision because it pinned the falsified
  claim and predates the restated law's strategy). Under D-L3 the key
  sequence of the deduped output is reversal-invariant; for full-key ties
  the kept occurrence is the file-order-first (documented in the L8
  Decision row).
- Registry-first rules for `mid`/`expensive`/`vision` are a faithful port
  (vectors `mid_*`, `expensive_*`, `vision_*`), not a law: nobody has
  stated the property they should satisfy. Candidate (T09, 2026-09-19):
  "an `expensive`/`vision` single-tier resolution never lands on a
  registry `tier: free` model" — `mid` is excluded because the ported
  Python rule deliberately accepts `free` there (`tier in ("paid","free")`).
  Cheapest mechanism: proptest over registries whose only `expensive`/
  `vision` match is a free-tier model, asserting fall-through to the
  stamped default.
- Direct-id path applies no credential gate (mirrors the shell). Candidate
  law once the shell is replaced: "every dispatched ref passed a gate".
  T09 note (2026-09-19): today `direct()` stamps `keyless: true`
  unconditionally (decision D2 (T09)), which makes that candidate vacuous until
  the tri-state lands; the mechanism is then the L2-block style assertion
  extended to the direct route (`Keyed(p)` ⇒ `credentials.contains(p)`).
- The tree is not rustfmt-clean: `cargo fmt --check` exits 1 with 38 hunks
  across `src/lib.rs` (21), `src/main.rs` (4), `tests/laws.rs` (6),
  `tests/vectors.rs` (7) (T01, 2026-09-19). Candidate law: "the tree is
  always `cargo fmt --check`-clean". Proposed mechanism: CI gate running
  `cargo fmt --check` — not a `tests/laws.rs` unit test.
- Kernel is not clippy-clean under `-D warnings`:
  `cargo clippy --release --all-targets -- -D warnings` exits 101 on
  `clippy::derivable_impls` at `tests/vectors.rs:41` (manual `impl Default
  for Override`) (T01, 2026-09-19). Candidate law: "kernel builds
  clippy-clean with `-D warnings`". Proposed mechanism: CI gate; one-line
  fix is `#[derive(Default)]` + `#[default]` on the `Fixture` variant.
- Duplicate catalog refs: the per-occurrence credential gate (see
  **Decisions** 2026-09-19, narrowed by L8/D-L3 the same day) is pinned by
  vectors, not by a law. Candidate law once the shell is retired: "the
  credential gate is a predicate of the catalog entry alone". Mechanism:
  vectors
  `T03_duplicate_ref_gate_is_per_occurrence` /
  `T03_duplicate_ref_shell_exit2_rust_still_ok` + the T03 differential
  (order itself never diverged on duplicates — L3 held on all 2250 cases).
- CLI exit/stdout contract (T04, 2026-09-19): exit ∈ {0 ok, 2 loud policy
  / usage, 3 unreadable input} and **stdout is empty on every non-zero
  exit** (a consumer piping stdout must never see a partial chain). No
  incident yet; mechanism exists — `tests/laws.rs::cli_*` runs the real
  binary. Candidate law: "non-zero exit never writes stdout".
- (RESOLVED 2026-09-19 by law **L8**, T16): duplicate catalog `ref`s (same
  `ref`, different `keyless`) all used to enter the chain
  (`T05_duplicate_ref_keeps_both_legs`; Python `sorted` keeps both too).
  L8 states "a chain never contains the same ref twice"; the dedup rule —
  keep the first occurrence in `catalog_order` (= best-ranked) — is

- The CLI emits one loud WARN per skip (E5-M2/E5-M5 phrasing), but no law
  covers WARN emission (main.rs is outside `tests/laws.rs`). T08 found the
  shell path swallowing the stamped catalog's E5-M2 WARN:
  `run-with-fallback.sh`'s CHAIN_META python runs the resolver with
  `capture_output=True` and only re-emits the inner stderr on failure, so a
  FANTASMA ref is skipped silently on the shell side while the kernel
  prints the WARN (vector `T08_dead_keyless_leg_skipped` pins the kernel
  skip). Candidate mechanism: CLI-level test asserting stderr contains
  "E5-M2" when a catalog ref is dead.
- Registry `id_status` is string-or-null in the wild. The kernel
  normalizes null → `""` (typed `Option`); the shell's direct-path python
  crashes with `TypeError: str + NoneType` when the matched model or a
  fallback id has `"id_status": null` (T08 repro: registry copy with
  `gpt-6-astra.id_status = null`). Candidate law once the shell is
  replaced: "id_status reaches the wire always as a string".
- (T10, 2026-09-19) **L3's mechanism is RED on main @ `1425b9c`**:

  `kernel/dispatch-policy/tests/laws.proptest-regressions`. Candidate
  mechanisms: tie-break the sort on `provider`, or make catalog refs
  unique (typed invariant). Decide before the Bend port copies the
  behaviour.
- (T10, 2026-09-19) The cross-implementation details a second consumer
