# Laws — P1 dispatch policy

A law is: **id · statement · incident it closes · mechanism that checks it**.
A law without a mechanism does not belong here (see `kernel/laws/README`
rule below). The Bend lab mirrors this file as `LAWS.bend`.

| Law | Statement (∀ inputs) | Incident | Mechanism |
|---|---|---|---|
| L1 | Chain fields are typed; the wire format `render_us`/`parse_us` round-trips exactly and a field containing a delimiter cannot become a chain | `e82f008` (TSV read keyless flag as provider "1") | type `ChainEntry { provider: Option<String>, keyless: bool }`; `tests/laws.rs::l1_us_wire_roundtrip`, `l1b_delimiters_are_rejected` |
| L2 | No entry whose registry `id_status` contains FANTASMA / NAO-ENCONTRADO / NAO-VERIFICADO ever appears in a cheap chain | E5-M2 | `l2_l4_l5_l6_cheap_gates`; vector `cheap_with_openrouter_credential` |
| L3 | Cheap order is keyless → context desc → ref asc, and is a pure function of catalog content | E5-M4 / R1 | `l3_cheap_order`; differential check vs `lib-oracfit-mode-loader.py resolve-tier` (identical on 2026-09-19 data, 11 refs) |
| L4 | A non-keyless entry appears only if its provider has a **file** credential; the environment is never an input | E5-M5 | `Inputs.credentials: &BTreeSet<String>` is the only credential input; `l2_l4_l5_l6_cheap_gates`; vector `cheap_zero_key_only` |
| L5 | The free route never yields a provider outside the owner allowlist; a catalog citing one is a violation, not a skip | E5-M6 / R4 | `l5_outside_allowlist_is_a_violation`; vector `cheap_provider_outside_allowlist_is_loud` |
| L6 | A chain is never empty; every failure is a typed `PolicyError`; no catalog ⇒ `CatalogMissing`, never a hardcoded default | E5 (dead default served as first option) | `Chain::new` rejects empty; `l6_no_catalog_never_defaults`; vectors `*_is_loud` |
| L7 | Gates filter but never reorder: a cheap chain is a subsequence of `catalog_order(catalog)` | (design, no incident yet) | `l2_l4_l5_l6_cheap_gates` (subsequence assertion) |

## Decisions

| Date | Behaviour | Why | Vector(s) that pin it |
|---|---|---|---|
| 2026-09-19 | A cheap-chain entry whose catalog `provider` is `null` skips both the allowlist and the credential gate even when `keyless: false`; on the wire it renders as `provider = ""` with `keyless = 0` | `None` is the typed "unknown provider" (never the text "1", incident e82f008); a gate on an unknown provider has nothing to check. The shell must treat `provider "" + keyless 0` as undispatchable rather than key-requiring | vector `T02_keyed_entry_unknown_provider_skips_credential_gate` (T02 report) |
| 2026-09-19 | Duplicate catalog refs are gated **per occurrence**, each by its own `provider`/`keyless`; every surviving occurrence enters the chain (no dedup, no collapse). | The shell reference (`run-with-fallback.sh` cheap branch) builds a `meta` dict keyed by ref — last file occurrence wins — and gates **all** occurrences of a ref alike. On duplicates with conflicting metadata the shell can exit 2 where Rust exits 0 (`T03_duplicate_ref_shell_exit2_rust_still_ok`) and keep N copies where Rust keeps fewer (`T03_duplicate_ref_gate_is_per_occurrence`). Differential T03 (2250 generated cases): 618 mismatches, **all** of this class, 0 order diffs, 0 other causes. Per-entry gating matches L4's own wording ("a non-keyless **entry** …") and the typed model; the collapse is a dict limitation of the shell. Rust supersedes the shell here — shadow comparisons (T08) must expect this exact divergence. | `T03_duplicate_ref_gate_is_per_occurrence`, `T03_duplicate_ref_shell_exit2_rust_still_ok` |
| 2026-09-19 | D1: an unknown `--format` value (anything ≠ `json`) renders the US wire format with exit 0 — no usage error, no diagnostic (`--format xml`, `--format jsn`, `--format ""` all behave as `us`) | US is the format the shell consumer parses; a typo falls back to the byte-compatible wire rather than failing a dispatch. Documented here because the main.rs doc comment advertises `[--format us\|json]` only | `tests/laws.rs::cli_unknown_format_value_falls_back_to_us`; T04 report Finding 1 |
| 2026-09-19 | Registry `models` **absent** = empty registry; `"models": null` = parse error, exit 3 (serde `default` covers absence, never explicit null). Ill-typed fields (`id_status: 5`, non-string `fallback`), 0-byte files and UTF-8 BOM are all exit 3 typed parse errors. | An explicit null or wrong-typed field is a malformed file, not an empty registry; loudness at the door. | T05 report (registry 2/4/5/8/9); complement pinned by `T05_empty_registry_cheap` |
| 2026-09-19 | Duplicate registry ids: the **last** `id_status` wins, deterministically (BTreeMap last-write in `status_map`). Verified identical across runs. | Any tie-break is arbitrary; last-write is documented and pinned rather than incidental. | `T05_duplicate_id_last_status_wins` |
| 2026-09-19 | Direct request `""` against a registry entry that lacks `id` → `MalformedField { field: "ref" }` (exit 2), not `UnknownModel` and not usage. An empty ref can never become a chain. | `Chain::new` rejects empty refs before anything dispatches (L1/L6); the typed error names the offending field. | `T05_direct_empty_id_is_malformed_not_chain` |
| 2026-09-19 | A catalog that fails to **parse** (`keyless:"true"`, `context_length:-1`, `context_length:1e6`, unreadable) is demoted to WARN + `CatalogMissing` exit 2 — unlike registry/allowlist (exit 3). Tampered and absent are conflated at the exit-code level; stderr stays typed and loud. | Matches the CLI shell's "tratado como ausente" stance (E5: never degrade to defaults); splitting the exit code is a candidate contract change raised by T05. | T05 report (catalog 10–12); terminal state pinned by `cheap_without_catalog_is_loud` |
| 2026-09-19 | Catalog `provider: ""` (empty string, not null) is a **real provider** in Rust → fails the allowlist → `ProviderOutsideAllowlist` exit 2. The shell tree coerces `""` → no provider (`m.get("provider") or ""` in run-with-fallback.sh) and then skips the credential gate — a real divergence; Rust is the louder side and the reference. | `Some("")` is a value, not an absence; silent falsy-coercion is the E5 disease. `sync-free-catalog.sh` asserts provider ∈ {opencode, openrouter}, so `""` is unreachable on synced data. | `T05_empty_provider_is_allowlist_violation` (divergence detailed in T05 report) |

## Rule for this directory

`kernel/laws/<pillar>.md` lists every law of that pillar with its mechanism.
CI check (to add with P2): every `L\d+` id in this file must appear in
`kernel/dispatch-policy/tests/` or `kernel/vectors/`. Presence-only, like
the AGENTS.md grep in bestmodel S25c — content honesty stays human.
Run byproduct: a red proptest writes `tests/*.proptest-regressions`
(next to the source) and replays it on every later run, so one discovered
counterexample turns the suite permanently red until the file is removed;
never commit it while the law it pins is still failing (T02).

## Not laws (yet)

- L3's determinism clause ("pure function of catalog content") currently
  holds only for catalogs with distinct `(keyless, context_length, ref)`
  triples: `catalog_order` sorts stable, so duplicate refs tie in FILE
  order and reversing the file reverses the chain
  (`laws::l3_cheap_order` fails at `PROPTEST_CASES=5000`, ~20 % of plain
  runs; T02). Candidate: total-order tie-break (e.g. append provider to
  the sort key) or a stamped-catalog invariant "refs are unique" plus a
  typed rejection. Pinned by vector `T02_l3_duplicate_ref_ties_keep_file_order`.
- Registry-first rules for `mid`/`expensive`/`vision` are a faithful port
  (vectors `mid_*`, `expensive_*`, `vision_*`), not a law: nobody has
  stated the property they should satisfy. Candidate: "a paid tier never
  resolves to a free-only provider".
- Direct-id path applies no credential gate (mirrors the shell). Candidate
  law once the shell is replaced: "every dispatched ref passed a gate".
