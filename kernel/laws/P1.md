# Laws — P1 dispatch policy

A law is: **id · statement · incident it closes · mechanism that checks it**.
A law without a mechanism does not belong here (see the "Rule for this
directory" section at the bottom of this file — T09, 2026-09-19: the
former `kernel/laws/README` pointer was dangling; no such file exists).
The Bend lab mirrors this file as `LAWS.bend` (to be generated; see
`docs/research/direction-kernel-rust-bend-lab-2026-09-19.md`).

## Decisions

Behaviour divergences a reader would otherwise call a bug. Each row: what,
why, when, and the vector that pins it.

| # | Behaviour | Why | Date | Pinned by |
|---|---|---|---|---|
| D1 | `ProviderOutsideAllowlist` (kernel exit 2) exists only in the Rust kernel. `bin/lib-oracfit-mode-loader.py resolve-tier` passes an outside-allowlist provider straight through, and the live shell path enforces the allowlist **post-hoc** (`bin/ledger-finalize.sh` marks the run `violado`). The kernel is stricter by design. | E5-M6/R4: the owner allowlist (`data/free-provider-allowlist.json`) is explicit policy; refusing pre-dispatch beats flagging a run after the prompt already left the machine. If dispatch suddenly exits 2 after a catalog sync, compare the `provider` fields of `data/free-catalog.json` against the allowlist file. | 2026-09-19 (T09) | vector `cheap_provider_outside_allowlist_is_loud` |
| D2 | On the non-cheap `tier:*` and direct routes, `keyless: true` means "credential gate not applied on this path", **not** "verified zero-key leg". The shell consumer must read `keyless` on those entries as not-applicable. | Mirrors `run-with-fallback.sh`, which applies the E5-M5 credential gate only on the `tier:cheap` leg. Proposed evolution: tri-state `Keyless \| Keyed(provider) \| Ungated` (wire gains a third value; `parse_us` accepts it). | 2026-09-19 (T09) | vectors `direct_id_with_fallback_and_statuses`, `expensive_outside_catalog_typed_unknown_provider` |
| D3 | A catalog entry with `keyless: false` and unknown (`null`) provider passes the credential gate and enters the cheap chain. | Mirrors the shell guard `[ -n "$PROVIDER" ]` (`run-with-fallback.sh`:82): no provider named, no gate to apply. ## Statement amendments (T09 law review, 2026-09-19)

Proposed precise wordings; the table keeps the short forms until the owner
folds them in. Each was checked against the mechanism by probe, not prose.

- **L1** — proposed statement: "∀ chains: `parse_us(r, render_us(c)) == c`;
  constructing a chain whose `ref`/`id_status`/`provider` contains US or LF
  (or whose `ref` is empty) fails with `MalformedField`." Verified by probe:
  a field containing CR survives the round-trip because the typed `keyless`
  bool renders last — do not reorder the four wire fields. Residual hole:
  `provider: Some("")` builds, renders as the empty field and parses back as
  `None` — the L1 generator (min-length-1 fields) cannot produce it, so the
  round-trip law does not bite there. Proposed mechanism: `Chain::new`
  normalizes (or rejects) an empty-string provider.
- **L2** — scope note: this law is cheap-route-only **by design**;
  `single_tier`/`direct` emit dead-stamped entries (probe: `tier:mid` on a
  FANTASMA-stamped default returns `Ok` with `id_status: "FANTASMA"`) and
  delegate the skip to the consumer, mirroring the shell's FANTASMA
  case-loop. Candidate law once the kernel replaces the shell: "no
  dispatched ref carries a dead id_status on any route"; mechanism: extend
  the door gate to `single_tier`/`direct`.
- **L3** — addendum: `context_length: null` orders as 0 and empty-`ref`
  catalog entries are dropped; both match Python `_catalog_order`
  byte-for-byte.
- **L4** — precise domain: "a non-keyless entry **with a known provider**
  appears only if…"; the unknown-provider keyed case is decision D3. The
  "environment is never an input" clause is structural (`Inputs.credentials`
  is the only credential input; no env read in `src/`), not test-enforced —
  a grep gate belongs in the P2 CI check.
- **L5** — precedence: the dead-id gate runs **before** the allowlist check,
  so a dead ref citing an outside provider is skipped (DeadId), not raised as
  a violation (probe: such a single-entry catalog yields `NoLiveRef`, not
  `ProviderOutsideAllowlist`). Proposed statement: "a **live** catalog entry
  citing a provider outside the owner allowlist is a violation, not a skip".
- **L6** — the third clause is free-route-scoped: `tier:<other>` without a
  catalog resolves via stamped defaults (that is the e82f008 contract), and
  `direct` ignores the catalog. The "`Chain::new` rejects empty" clause is
  enforced by the type (private `entries`), not by any named test — cheap to
  pin with a one-line test in `tests/laws.rs`.
- **L7** — no amendment; the subsequence assertion is cursor-correct and
  duplicate refs cannot bypass it.

## Rule for this directory

`kernel/laws/<pillar>.md` lists every law of that pillar with its mechanism.
CI check (to add with P2): every `L\d+` id in this file must appear in
`kernel/dispatch-policy/tests/` or `kernel/vectors/`. Presence-only, like
the AGENTS.md grep in bestmodel S25c — content honesty stays human.

## Not laws (yet)

- Registry-first rules for `mid`/`expensive`/`vision` are a faithful port
  (vectors `mid_*`, `expensive_*`, `vision_*`), not a law: nobody has
  stated the property they should satisfy. Candidate (T09, 2026-09-19):
  "an `expensive`/`vision` single-tier resolution never lands on a
  registry `tier: free` model" — `mid` is excluded because the ported
  Python rule deliberately accepts `free` there (`tier in ("paid","free")`).
  Cheapest mechanism: proptest over registries whose only `expensive`/
  `vision` match is a free-tier model, asserting fall-through to the
  stamped default.
- Direct-id path applies no credential gate (mirrors the shell). Candidate
  law once the shell is replaced: "every dispatched ref passed a gate".
  T09 note (2026-09-19): today `direct()` stamps `keyless: true`
  unconditionally (decision D2), which makes that candidate vacuous until
  the tri-state lands; the mechanism is then the L2-block style assertion
  extended to the direct route (`Keyed(p)` ⇒ `credentials.contains(p)`).
